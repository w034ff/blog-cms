# サイトの設定 要件定義

- 状態: 実装済み（2026-10-15）。共有用の画像（§9）は 2026-10-18
- 作成: 2026-10-15、サイトの名前を「Small Diffs」に決めた後、管理者が画面から名前を変えられるようにする相談から
- 関連: `docs/project-status.md` §3・§7.3、`app/shared-metadata.ts`、`lib/dal.ts`

管理者が、サイトの名前・説明文・共有用の画像を管理画面から変えられるようにする機能の設計記録。画面での名前は「サイトの設定」、コードと URL での名前は `settings`。

---

## 1. 目的と前提

サイトの名前と説明文は `app/shared-metadata.ts` の定数で、変えるにはコードを直して PR を出す必要があった。CMS として、WordPress の「一般設定」にあたる最小限の画面を持たせる。

対象は名前と説明文、それに共有用の画像（§9）である。ロゴの画像とファビコンは先送りにしている（§7）。ファビコンは決まったファイル（`app/icon.svg`）から配っており、その仕組みを変える必要があるため（オーナー、2026-10-15）。

## 2. 決定

- 値は DB の設定の表に持つ。行が無いときは、`app/shared-metadata.ts` の `DEFAULT_SITE_NAME`・`DEFAULT_SITE_DESCRIPTION` を使う。移行の直後も、設定を一度も保存していない環境も、今と同じ表示になる。
- 変えられるのは管理者（`users.role = 'admin'`）だけ。著者には画面もメニューも出さず、Server Action も拒む。
- 変えた値は、次に開いたページから反映する。公開ページはすべて毎回描いている（`force-dynamic`）ので、キャッシュの作り直しは要らない。

## 3. データ

`app_settings`（`key` TEXT 主キー、`value` TEXT NOT NULL）。`docs/project-status.md` §7.3 で複数の著者の参加方針（`authorAccessMode`）を置くと決めてある表と同じもので、この機能で先に作る。移行は `db:generate` → `db:migrate` の経路で作る（`docs/project-status.md` §2）。

| key                | value                                     | 既定（行が無いとき）       |
| ------------------ | ----------------------------------------- | -------------------------- |
| `site_name`        | サイトの名前。前後の空白を除き 1〜40 文字 | `DEFAULT_SITE_NAME`        |
| `site_description` | 説明文。前後の空白を除き 0〜120 文字      | `DEFAULT_SITE_DESCRIPTION` |

- 文字数は文字（コードポイント）で数える。上限は名前の付いた定数にする（`SITE_NAME_MAX_CHARS`・`SITE_DESCRIPTION_MAX_CHARS`）。
- 説明文を空にして保存したら、空のまま使う（既定に戻さない）。名前は空を許さない。
- 改行は許さない（どちらも 1 行の文字として使われるため）。

## 4. 読む側

設定を読む関数を 1 つ（`lib/` の下、`server-only`、React の `cache` で 1 回の描画に 1 回だけ読む）作り、名前と説明文を使うところはすべてそこから読む。

| 使うところ                                                   | 今                                      | 変えた後                                                                 |
| ------------------------------------------------------------ | --------------------------------------- | ------------------------------------------------------------------------ |
| ページのタイトルの型（`%s \| 名前`）、既定のタイトル、説明文 | `app/layout.tsx` の `metadata` の定数   | `generateMetadata` で読む                                                |
| `og:site_name`、共有用の画像の代替テキスト                   | `sharedOpenGraph`（7 つのページが展開） | 名前を受けて作る関数にし、各ページの `generateMetadata` で読んだ値を渡す |
| ヘッダーのブランド                                           | `SiteHeaderNav` が定数を読む            | `SiteHeader`（サーバー）が読んで渡す                                     |
| フッター                                                     | `SiteFooter` が定数を読む               | サーバーで読む                                                           |
| RSS のチャンネルの名前と説明                                 | `lib/rss.ts` が定数を読む               | `app/rss.xml/route.ts` が読んで渡す                                      |
| 編集画面が画面側で付けるタブのタイトル（`tabTitle`）         | 定数の型                                | 名前をサーバーから受けて付ける                                           |

変えないもの:

- Figma の埋め込みが名乗る名前（`lib/embed-provider.ts` の `FIGMA_EMBED_HOST`）。サイトの名前と切り離してある。
- 画像に焼き込んだ名前: 既定の共有用の画像 `public/og.png`。画面から名前を変えても、これは古い名前のままである。作り直すには `scripts/make-og-image.mts` を流すか、共有用の画像を差し替える（§9）。リンクカードのマークは名前を持たない（`docs/category-mark-requirements.md` §3.3）。

## 5. 管理画面

- `/admin/settings`。見出しと画面のタブのタイトルは「サイトの設定」。管理者でなければ 404（`verifyAdmin`）。
- 左メニュー（`AdminSideNav` の `adminNavItems`）の最後、「タグの管理」の下に「サイトの設定」を足す。管理者だけに出す（タグの管理と同じ）。
- フォームは 3 つの欄と「保存」のボタン。3 つ目の「共有用の画像」は §9。
  - 「サイトの名前」: 1 行の入力欄。必須。
  - 「説明文」: 1 行の入力欄。補足に「ページの説明、共有したときの説明、RSS に使います」。
  - 欄の下に、残りの文字数ではなく「12 / 40」の形で今の文字数と上限を出す。
- ブランドの名前は 40 文字まであり得るので、ヘッダーでは名前の文字が切れて「…」になり、メニューより先に縮む。名前はリンクの読み上げの名前（`aria-label`）なので、切れても全部が読まれる（`docs/site-header-requirements.md` §3.4）。
- 保存は Server Action。管理者かを DB で確かめ直し（`isAdmin`）、値を検証してから書く。結果は次のどれかを返し、画面に出す。
  - 保存した: 「保存しました」を欄の上に出す。ヘッダーの名前も、ページを描き直して新しい名前にする。
  - 値が不正: 欄ごとに理由（「名前を入力してください」「40 文字以内で入力してください」「改行は使えません」）。DB は変えない。
  - 管理者でない: タグの管理の Action と同じく、理由（「サイトの設定は管理者だけが変えられます。」）をフォームの上に出す。セッションが切れていれば `isAdmin` がログイン画面へ送る。どちらも DB は変えない。
- 既定の共有用の画像に焼き込んだ名前は変わらないことを、共有用の画像の欄で伝える（§9）。リンクカードの絵は名前を持たないので書かない。

## 6. 受け入れ基準

| ID  | 基準                                                                                                        | 測り方                                                                                         |
| --- | ----------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 1   | 設定の行が無いとき、名前と説明文は既定の値で、今と同じ表示になる                                            | `app/actions/settings.test.ts`                                                                 |
| 2   | 保存した名前と説明文が、タイトル、`og:site_name`、ヘッダー、フッター、RSS、編集画面のタブに出る             | `e2e/site-settings.spec.ts`                                                                    |
| 3   | 管理者でない人が Server Action を呼んでも拒まれ、DB は変わらない                                            | `app/actions/settings.test.ts`                                                                 |
| 4   | 空の名前、上限を超える文字数、改行を含む値は、理由を返して保存されない                                      | `lib/site-settings-rules.test.ts`、`app/actions/settings.test.ts`、`e2e/site-settings.spec.ts` |
| 5   | 著者には左メニューに「サイトの設定」が無く、`/admin/settings` は 404 になる                                 | `e2e/site-settings.spec.ts`                                                                    |
| 6   | 管理画面で名前を変えて保存すると、その画面のヘッダーの名前が変わる                                          | `e2e/site-settings.spec.ts`                                                                    |
| 7   | 共有用の画像を選んで保存すると公開ページの `og:image` がその画像になり、解除して保存すると `/og.png` に戻る | `e2e/site-settings.spec.ts`                                                                    |
| 8   | 共有用の画像の値は、空か `/uploads/` のファイルだけを受け付ける                                             | `lib/site-settings-rules.test.ts`                                                              |
| 9   | 設定が参照する画像は `gc:uploads` に消されない                                                              | `scripts/upload-refs.test.ts`                                                                  |

E2E の名前の変更は、ほかの spec と同じサーバーで並んで走るので、既定の名前を頭に残した名前にする。ほかの spec はヘッダーのリンクを名前の部分一致で探し、編集画面のタブのタイトルは「 | 」の前だけを比べる（`e2e/site-settings.spec.ts` の冒頭のコメント）。

## 7. 先送り

- **ロゴの画像とファビコン**（2026-10-18 に共有用の画像と分けて先送り）。今のマークは 2026-10-15 にオーナーが選んだもので、差し替える予定がまだ無い。作るときの形:
  - 欄は §9 と同じ形で 2 つ足す（「ロゴ」「ファビコン」）。保存の値と掃除も §9 と同じ。
  - ファビコンは `app/icon.svg`・`app/favicon.ico`・`app/apple-icon.png` の決まったファイルをやめ、`app/layout.tsx` の `generateMetadata` の `icons` で、設定の画像か既定のファイルを指す。ICO と 180px の PNG を作るには、アップロードを縮める処理（`lib/upload-image.ts`）に正方形への切り出しを足す必要がある。
  - ヘッダーのマーク（`components/SiteMark.tsx`）は、設定の画像があればそれを同じ大きさで描く。マークは配色に合わせて反転するが、アップロードした画像は反転しないので、暗い配色での見え方を確かめる。
  - 手間は §9 の 2〜3 倍と見込む。
- 画像に焼き込んだ名前を、名前を変えたときに作り直すこと（§4）。共有用の画像を画面から作り直すと、日本語のフォントの扱いに戻る（`docs/project-status.md` §4 の OGP）。
- 名前と説明文のほかの設定（記事の 1 ページの件数など）。

## 8. 複数の著者との関係

設定の表は、複数の著者の参加方針（`authorAccessMode`、`docs/project-status.md` §7.3）も置く表である。「サイトの設定」の画面は、参加方針の切り替えを置く場所の候補でもある。そのときは、この画面に欄を足すか、利用者の管理（`/admin/users`）に置くかを決める。

## 9. 共有用の画像

管理者は、ページを共有したときの画像（`og:image`）を 1 枚差し替えられる。画面から名前を変えると既定の `public/og.png` には古い名前が残る（§4）ので、そのときに作り直さずに差し替えられるようにする。

- 値は `app_settings` の `site_share_image`。`/uploads/<ファイル名>` か `''`。行が無いときと `''` は既定の `/og.png` を使う。検証は `lib/site-settings-rules.ts` で、それ以外の値は保存しない（ブラウザからは選べない値なので、理由は「画像を選び直してください」の 1 つ）。
- 欄は説明文の下の「共有用の画像」。形と文言は記事の設定のサムネイル（`components/editor/ThumbnailField.tsx`）に合わせる: 小さなプレビュー、状態の文（「指定した画像」／「既定の画像」）、「画像を選ぶ」（指定済みなら「変更」）と「解除」。補足は「共有したときの画像に使います。1200×630 px がおすすめです。」。既定の画像を使っている間だけ、プレビューの下に「既定の画像には「Small Diffs」の名前が描かれていて、サイトの名前を変えても変わりません。」と出す（名前は `public/og.png` を描いた `DEFAULT_SITE_NAME`）。この注意は既定の画像にしか当てはまらないので、画像を選ぶと消える。
- 画像を選んだ時点で `/api/uploads` に送る。形式・大きさの上限・加工は本文の画像と同じ。設定に書くのは「保存」を押したとき。保存せずに離れると、送った画像はどこからも参照されず、`gc:uploads` が猶予の後に消す。
- `sharedOpenGraph`（`app/shared-metadata.ts`）が設定の画像を `og:image` にする。`width`・`height` は書かない。記事のサムネイルと同じく、アップロードの大きさは分からず、違う値はカードを歪めるため。サムネイルのある記事は、引き続き記事のサムネイルが優先する。
- 掃除: `scripts/upload-refs.mts` の `referencedInDb` が `app_settings` の値も数える。
- 退けた案（2026-10-18）: ロゴとファビコンも一緒に差し替える案は §7 に先送り。名前を変えたら共有用の画像をサーバーで描き直す案は、日本語のフォントを配る問題（`docs/project-status.md` §4 の OGP）に戻るので採らない。

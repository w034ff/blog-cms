# カテゴリ色のマーク 要件定義

- 状態: 設計済み、未実装（2026-10-17）
- 作成: 2026-10-17、`docs/project-status.md` §6「画像の無い記事のカード」を、2026-10-15 に決めたサイトのマーク（±）を前提に決め直す相談から
- 関連: `docs/link-card-requirements.md` §17、`cms-features.md「見送り・現状維持の決定」§4`、`lib/site-mark.ts`、`lib/thumbnail.ts`、`components/PostCard.tsx`

画像を持たない記事に、そのカテゴリの色で塗ったサイトのマークを出す機能と、狭い画面の記事一覧を軽くする変更の設計記録。デザインの案と実寸の描き比べは https://claude.ai/artifact/MBBmpn8B9vrDU5WDNEsDY6 にある（案 H と、その暗い配色・狭い画面の版）。

---

## 1. 目的と前提

**目的**: 文字だけの記事は、記事一覧に絵が何も出ない。サムネイルを持つ記事と並ぶと、その行だけ右が空く。リンクカードの側は §17（`docs/link-card-requirements.md`）でサイトのマークを既に出しているので、一覧とカードで「画像の無い記事」の見え方が食い違ってもいる。

**前提**: 公開中の記事は 4 本で、どれも画像を持たない（2026-10-15 時点）。入れれば一覧の全行に絵が付く。カテゴリは公開のときに必ず選ばれている（`lib/content.ts` の `normalizeCategory` と公開の検査）。

作者がこの穴について以前に出した答えは「サイト側で持つ、タイトルを書いたカード」だった（`cms-features.md「見送り・現状維持の決定」§4`）。タイトルを書く案は §6 の理由で採らず、その代わりにカテゴリの色を使う。

## 2. 決定

- **画像の無い記事の絵は、カテゴリの色の薄い地に、カテゴリの色で塗ったマークを置いたものである。** マークの形はサイトのマーク（`lib/site-mark.ts`）そのもので、記号の「±」は `--surface` の色で抜く。
- **記事一覧とリンクカードで同じ絵を使う。** リンクカードの、地が灰色で「± と Small Diffs」を描いた絵（`docs/link-card-requirements.md` §17 の旧形）はこれに置き換える。
- **外部カードには出さない。** 理由は `docs/link-card-requirements.md` §17 のまま — このブログが書いていないページに、このブログのマークを乗せないため。
- **狭い画面（`sm` 未満）の記事一覧は、説明文とタグを出さない。** サムネイルの枠は今の 128×80 のままで、写真と、この絵とが同じ枠に入る（§5）。
- **`resolveThumbnail` は変えない。** この絵は記事の画像ではなく、一覧とカードの調度である。`og:image` は `/og.png` のままで、アップロードの掃除の対象にもならない（`docs/link-card-requirements.md` §17.2 の理由と同じ）。

## 3. 絵

### 3.1 色

すべて既存の変数から作る。新しい色の変数は足さない。

| 部分                 | 値                                                              |
| -------------------- | --------------------------------------------------------------- |
| 地                   | `color-mix(in srgb, var(--category-color) 12%, var(--surface))` |
| 枠線（記事一覧だけ） | `color-mix(in srgb, var(--category-color) 30%, var(--surface))` |
| マークのタイル       | `var(--category-color)`                                         |
| 記号「±」            | `var(--surface)`                                                |

`--category-color` は `.category-mark[data-category=…]` が既に使っている名前で、`--category-tech` と `--category-blog` を指す。明るい配色と暗い配色の切り替えは、この 2 つと `--surface` が受け持つので、絵の側に配色ごとの分岐は無い。

記号を `--surface` で抜くのは、`lib/site-mark.ts` の `MARK_LIGHT` / `MARK_DARK` と同じ考え方である（タイルは前景、記号は地）。

算出したコントラスト（記号とタイル。WCAG 1.4.11 の 3:1 が基準）:

| 配色   | 技術記事                      | ブログ                        |
| ------ | ----------------------------- | ----------------------------- |
| 明るい | 3.58（`#e8590c` と白）        | 4.37（`#2b8a3e` と白）        |
| 暗い   | 7.59（`#ff8a4c` と zinc-900） | 8.83（`#51cf66` と zinc-900） |

明るい配色の技術記事が最も低い。地を 15% にすると記号ではなくタイルと地の差が 3:1 を割るので、12% にした。

暗い配色のリンクカードの地（技術記事で `#342621`）は、カードのホバーの塗り（`#161b22`）と見分けられる。`docs/link-card-requirements.md` §17.3 が決めている「ポインタが乗っているあいだも絵の区画がカードから見分けられる」はそのまま満たす。

### 3.2 大きさ

**マークは枠の高さの 40% の正方形で、枠の中央に置く。**

| 枠                       | 枠の寸法                                                   | マーク  |
| ------------------------ | ---------------------------------------------------------- | ------- |
| 記事一覧（`sm` 以上）    | 160×96                                                     | 約 38px |
| 記事一覧（`sm` 未満）    | 128×80                                                     | 32px    |
| リンクカード（広い画面） | `--link-card-image-width` × カードの高さ                   | 約 54px |
| リンクカード（320px）    | 約 95×102（`docs/link-card-requirements.md` §17.2 の実測） | 約 41px |

リンクカードの枠の寸法は `docs/link-card-requirements.md` §16.1 のもので、この機能では動かさない。同 §17.2 が狭い画面で内側の余白を減らしていたのは、文字（Small Diffs）を読める大きさに保つためだった。この絵は文字を持たないので、余白の調整は要らなくなる。

### 3.3 描き方

**インラインの `<svg>` で描き、幾何は `lib/site-mark.ts` の定数から作る。** 静的な画像ファイルは持たない。

- **理由**: 色が CSS の変数で決まるので、配色ごとのファイルと `<picture>` が要らない（`docs/link-card-requirements.md` §17.3 が 2 枚のファイルを持っていたのは、画像として読み込んだ SVG がページの変数を読めないからである）。読み込みの失敗も起きない。幾何の写しが 1 つ減り、`lib/site-mark.test.ts` が静的ファイルと定数を突き合わせる必要もなくなる。
- 公開側のリンクカードは `lib/rehype-link-card.ts` が作る。サニタイズの後の段なので、`<svg>` を許可リストに足す必要は無い（`docs/link-card-requirements.md` §6.1）。
- `<svg>` は `aria-hidden="true"` を持つ。カードと一覧の行は、隣のタイトルで名前が付いている。
- 色は属性に書かず、class と `data-category` で CSS から当てる。

形は次のとおり。枠の class は面ごとに違い（リンクカードは `link-card-image`、カード検索の結果は `link-card-result-image`）、枠の寸法と位置は今の規則がそのまま受け持つ。

```html
<span class="link-card-image category-art" data-category="tech">
  <svg viewBox="0 0 32 32" aria-hidden="true" focusable="false">
    <rect class="category-art-tile" width="32" height="32" rx="7" />
    <path
      class="category-art-glyph"
      d="M16 7v8M12 11h8M12 22h8"
      fill="none"
      stroke-width="3"
      stroke-linecap="round" />
  </svg>
</span>
```

`CardImage`（`lib/link-card-image.ts`）は、`src` を持つ写真と、カテゴリを持つマークの 2 つの形を区別する型になる。マークの形は `src` を持たない — 描くのはファイルではなくなるからである。`docs/link-card-requirements.md` §17.2 の「`src` から後で見分けはしない」はそのまま守る。

### 3.4 カテゴリが無いとき

型の上ではカテゴリが `''` の記事がありうる（下書きの間）。公開中の記事は必ずカテゴリを持つので、公開側の記事一覧と公開のリンクカードには来ない。エディタのカード検索と挿入ダイアログは下書きも見せうるので、そこで `''` が来たら、`--category-color` が `--foreground` に落ちる。§3.1 の式はそのままで、タイルは前景色、地は前景色を 12% 混ぜた灰色になる（サイトのマークそのものの配色）。カテゴリを推測して色を付けることはしない。

## 4. 出す場所

| 面                                                       | 今                          | これから                                                         |
| -------------------------------------------------------- | --------------------------- | ---------------------------------------------------------------- |
| 記事一覧（`/`、`/tags/[tag]`、`/categories/[category]`） | 何も出さない                | マークを出す                                                     |
| 公開ページのリンクカード（内部）                         | 灰色の地に ± と Small Diffs | マークを出す                                                     |
| エディタのリンクカード（NodeView）                       | 同上                        | マークを出す（公開と同じ、`docs/link-card-requirements.md` §13） |
| エディタのカード検索の結果の行                           | 同上（小さな版）            | マークを出す                                                     |
| 挿入ダイアログの記事の行（`InsertDialog.tsx`）           | 同上                        | マークを出す                                                     |
| 外部カード                                               | 文字だけ                    | 変えない                                                         |
| `og:image`                                               | `/og.png`                   | 変えない                                                         |
| 管理画面の記事一覧（`PostListRows.tsx`）                 | 何も出さない                | 変えない（§7）                                                   |
| 走り書きの一覧、検索の結果                               | 絵を持たない                | 変えない                                                         |

エディタの 3 面は、公開のカードと同じ判定（`internalCardImage`）を通る。`docs/link-card-requirements.md` §13 と同 §16.4 が記録しているとおり、面ごとに絵を決めると同じ記事が違う絵で描かれる。

## 5. 狭い画面の記事一覧

**`sm` 未満では、記事一覧の行は タイトル・日付・カテゴリ・サムネイル だけになる。** 説明文とタグは出さない。`sm` 以上は今のまま（説明文 2 行、タグ）。

- **理由**: 360px でサムネイルの横に残る列は約 184px で、そこにタイトル・日付・カテゴリ・説明文 3 行・タグを積むと、1 行が約 300px になる。外すと約 200px になり、サムネイルとの高さも釣り合う。
- **他のサイトの実測（2026-10-17、Chrome DevTools MCP、360px と 1280px）**: ガジェッター（gadgeteer.jp）と Zenn は、どちらの幅でも説明文とタグを出さない。ガジェッターは左に 160×90 の画像、Zenn は左に約 72px 角の絵文字のタイルを置き、どちらも全行が同じ大きさの枠である。Qiita は画像も説明文も持たず、タグだけを 360px でも全部出す。
- **広い画面で説明文を残す理由**: 3 サイトは集約型で、行の残りを著者や数が埋めている。このブログの行にはそれが無く、説明文が中身の手がかりになる。
- **タグを外してよい理由**: タグのページには記事のページとヘッダーの「記事 ▾」からたどれる。Qiita がタグを残せるのは、画像の枠を持たず全幅の行を使えるからである。
- 説明文の行数（スマホで 3 行、`sm` から 2 行）は `components/PostCard.tsx` のコメントが述べている決定で、これは「スマホでは出さない、`sm` から 2 行」に変わる。
- 隠すのは CSS（`hidden sm:block` の形）で行う。HTML から消さないので、支援技術と検索エンジンには今と同じものが届く。

## 6. 却下した案

描き比べは冒頭のキャンバスにある。

- **F ± のタイル（リンクカードと同じ灰色の絵を一覧にも出す）** — 実装は最も小さい。公開中の記事がどれも画像を持たないので、一覧の全行がまったく同じタイルになり、読み込みに失敗した画像のように見える。
- **G ± とタイトル** — 作者が以前に挙げた形に最も近い。枠の中のタイトルが、すぐ左のタイトルと同じ文字の二重になる。リンクカードでも同じことが起きる。
- **2026-10-15 の 5 案（A タイトル、B カテゴリ色、C 表紙ダーク、D サイトのマーク、E 頭文字）** — どれもマークが決まる前の案で、アクセントの罫を使っていた。B の「カテゴリの色の地」は H に引き継いだ。E（頭文字）は、日本語の題で 1 文字目が「ブ」のように意味を持たないことが多い。
- **狭い画面だけ枠を 64×64 の正方形にする** — 文字の列は広がるが、写真の枠と大きさが変わる。写真・絵文字・空白が混ざると一覧が不揃いに見える、という絵文字のアイキャッチを見送った理由（`cms-features.md「見送り・現状維持の決定」§4`）にまた当たる。§5 の形なら枠を変えずに済む。
- **狭い画面ではマークを出さない** — 文字の列は最も広いが、画像の無い記事は狭い画面で何も出ないままになり、この機能の目的が電話で消える。
- **カテゴリの色を 15% 混ぜた地** — §3.1。明るい配色の技術記事で 3:1 を割る。
- **CSS の `mask` で 1 枚の静的ファイルを塗る** — 色は変数で決められるが、ファイルが 404 になると要素ごと見えなくなる。`docs/link-card-requirements.md` §17.5 が `naturalWidth` を測っていたのと同じ種類の失敗を、インラインの `<svg>` なら持たない。

## 7. 先送り

- **いいねの数を一覧に出す。** 書き手が 1 人の今は、自分の記事にいいねを付けられないので数は常に 0 で、0 件の行には何も出さない（`docs/library-requirements.md` §6.3）。公開側に数を出すかも同 §7 で保留である。出すときの位置は、日付とカテゴリの行の末尾（Zenn・ガジェッターと同じ）を想定している。
- **狭い画面のタイトルの大きさ。** 24px のままなので、184px の列で 2〜3 行に折り返す。測った 3 サイトは 13.6px（ガジェッター）、15.75px（Zenn）、20px（Qiita）だった。
- **管理画面の記事一覧のサムネイル。** 管理画面は自分の記事を探す場所で、カテゴリの色を出す理由が公開側ほど無い。
- **検索の結果の種類の札の地**（`docs/search-requirements.md` §7）。そちらは「一覧をカードの形にするとき」に決めるとしている。この機能は一覧の行の形を変えない（カードにはしない）ので、決めずに残る。

## 9. 他の文書への影響

この機能を入れる PR で、次を今の事実に書き直す。

- `docs/link-card-requirements.md` §17 — 絵が「灰色の地に ± と Small Diffs」から「カテゴリ色のマーク」に変わる。同 §17.3（配色ごとの 2 枚のファイルと `<picture>`）は、インラインの `<svg>` に置き換わった理由を 1〜2 行残して書き直す。同 §17.4 の最後の項目（記事一覧にも同じマークを出す — 保留）は決定に変わる。同 §17.5 の 17c（記事一覧は変わらない）と 17d は、この文書の §8 に移る。
- `cms-features.md「見送り・現状維持の決定」§4` — 「作者が考えている答えは、タイトルを書いたカード」を、この文書で決めた答えに書き直す。
- `docs/project-status.md` §6「画像の無い記事のカード」 — 先送りの一覧から外す。
- `components/PostCard.tsx` のコメント（説明文の行数、「画像を持つ記事が少ないので枠を取らない」）。

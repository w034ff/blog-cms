# 複数の著者 要件定義

- 状態: 設計（2026-10-17）
- 作成: 2026-10-17、`docs/project-status.md` §7 の複数の著者のうち、OAuth なしで作れる部分を先に作る相談から
- 関連: `docs/project-status.md` §7、`docs/site-header-requirements.md` §3.3・§8、`docs/library-requirements.md`、`lib/dal.ts`、`lib/posts.ts`

複数の著者が 1 つのサイトに書けるようにするための設計記録。全体の方針（Google でのログイン、役割、参加方針）は `docs/project-status.md` §7 が持つ。この文書はその実装を、OAuth の前に作れる第 1 段（この文書の §1〜§8）から書き、OAuth の段は後から末尾に足す。

---

## 1. 目的と前提

著者がログインできるようになる前に、ログインした著者ができることの境界を固める。今は役割（`users.role`）と記事の著者（`posts.authorId`）の列があるだけで、境界はほとんど強制されていない。ログインした利用者なら誰でも、他人の記事を編集・公開・削除でき、他人の下書きのプレビューや版の履歴も開ける。

今の本番に著者はおらず、管理者 1 人だけである。著者のアカウントは E2E の準備（`e2e/prepare-db.mts`）が作るテスト用のものだけで、第 1 段の強制はそれで確かめる。

## 2. 決定

- **記事の編集・公開・非公開化・削除・版の復元は、その著者か管理者だけ**。著者の無い行（`authorId` が null）は管理者だけ。他人の行への操作は、DB を変えずに拒む。
- **停止は、ログインと書き込みを止め、公開側からその著者の行を外す**。行は消さず、公開状態も書き換えない。停止を解けば、元の公開状態にそのまま戻る（オーナー、2026-10-17）。消したい行は、管理者が 1 本ずつ消す。
- 管理者は停止できない。管理者が自分を締め出さないため。
- **表示名を持ち、空でなければ記事と走り書きのページに署名として出す**（オーナー、2026-10-17）。表示名は本人が「アカウントの設定」で決める。空のうちは署名を出さないので、管理者が表示名を入れるまで今の見た目は変わらない。
- エディタのタグ欄から辞書にタグを足す操作（`/api/tags`）は、著者にも許す（今と同じ）。辞書の編集・統合・削除は管理者だけのまま。
- 利用者の管理画面（`/admin/users`）は OAuth の段で作る（§8）。第 1 段の停止は、データと強制とテストまでである。

## 3. データ

移行は `db:generate` → `db:migrate` の経路で作る（`docs/project-status.md` §2）。

| 列                   | 型                       | 中身                                                                   |
| -------------------- | ------------------------ | ---------------------------------------------------------------------- |
| `users.display_name` | TEXT NOT NULL DEFAULT '' | 公開側に出す名前。前後の空白を除き 0〜20 文字、改行なし。`''` は未設定 |
| `users.suspended_at` | TEXT NULL                | 停止した時刻（ISO 8601）。null なら停止していない                      |

- 上限の 20 は、署名が幅 360px の画面で日付の行に収まる長さから決めた（§6.2。オーナー、2026-10-17）。日本語の名前と、英字のハンドルや併記がおおむね入る。上限は名前の付いた定数にする（`DISPLAY_NAME_MAX_CHARS`）。数え方は `docs/site-settings-requirements.md` §3 と同じく文字（コードポイント）。
- `username` はログイン用のまま、公開側には出さない。

## 4. 所有の強制

### 4.1 判定

「この利用者がこの行を書き換えてよいか」を、1 つの純粋な関数が答える（`lib/` の下）。入力は、利用者の id と役割、行の `authorId`。管理者なら常に可、著者なら `authorId` が自分の id のときだけ可。この関数を vitest で確かめ、各経路はそれを呼ぶだけにする。

### 4.2 経路ごとの扱い

| 経路                                                                          | 他人の行に対して                                                     |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| `submitPostAction`（公開・更新・非公開化）                                    | 拒む。結果に `forbidden` を返し、エディタは理由を出す                |
| `deletePostAction`                                                            | 拒む。DB を変えない                                                  |
| `/api/drafts`（自動保存）                                                     | 403。エディタは「保存に失敗」を出す                                  |
| `restoreRevisionAction`                                                       | 拒む。DB を変えない                                                  |
| 編集画面、版の履歴の画面、Markdown の書き出し（`/admin/posts/<id>/markdown`） | 404                                                                  |
| 下書きのプレビュー（`/posts/<slug>`、`/scribbles/<slug>`）                    | ログインしていない人と同じく 404                                     |
| 管理画面の記事一覧と走り書きの一覧                                            | 著者には自分の行だけを出す。管理者にはすべてを出す                   |
| カードの検索（`/api/posts/search`）                                           | 公開中の行と自分の下書きだけを返す。他人の下書きのタイトルを出さない |

- 新しい行は、作成した利用者を著者にする（今と同じ。`lib/posts-write.ts` の `createPost`）。
- `forbidden` の文言は「この記事を編集する権限がありません。」。
- 他人の行を 403 や `forbidden` で拒むのは、操作の結果だけである。ページを開く経路は、行の有無を明かさないため 404 にする（`verifyAdmin` が 403 ではなく 404 にしているのと同じ理由）。

### 4.3 ログインしていれば誰でもよい経路

画像のアップロード（`/api/uploads`）、タグの追加（`/api/tags`）、リンクの情報の取得（`/api/link-preview`・`/api/link-title`・`/api/link-image`）、ライブラリの操作（`app/actions/library.ts`）。停止中の利用者はログインしていない扱いになるので（§5）、ここも止まる。

## 5. 停止

- **ログイン**: パスワードが合ったうえで停止中なら、セッションを作らず「このアカウントは停止されています。」を返す。パスワードが違うときの文言は今のまま。
- **既存のセッション**: セッションの読み込み（`lib/dal.ts` の `getOptionalSession`・`verifySession`）が利用者の行を DB で確かめ、行が無いか停止中なら、セッションが無いものとして扱う。ページは `/login` へ送り、Route Handler は 401 を返す。役割と同じく、停止は次の要求から効く（`isAdmin` が DB を読むのと同じ理由）。
- **公開側**: 公開中の行の読み込み（`lib/posts.ts` の `listed` と `publishedBySlug`）に「著者が停止中でない」を足す。これで次のすべてから外れる: ホーム、タグとカテゴリのページ、走り書きの一覧と各ページ（404）、記事のページ（404）、検索、RSS、リンクカード（`resolveCard` は存在しない記事と同じく普通のリンクにする）、件数。著者の無い行は外さない。
- **ライブラリ**: ほかの利用者のライブラリからも、停止中の著者の行を外す（公開中でない行を出さないのと同じ扱い）。いいねとブックマークの行は消さない。
- 停止と解除の操作は第 1 段では画面に出さない（§2）。テストは DB の列を直接書いて確かめる。

## 6. 表示名と署名

### 6.1 アカウントの設定

- `/admin/account`。見出しと画面のタブのタイトルは「アカウントの設定」。ログインしていれば誰でも開ける（自分の行だけを扱う）。
- ヘッダーのアカウントのメニューに「アカウントの設定」を足す。位置は「ライブラリ」の上。管理画面の左メニュー（`AdminSideNav`）には足さない。
- 欄は「表示名」の 1 つと「保存」のボタン。補足に「記事と走り書きのページに著者名として出ます。空にすると出しません。」。欄の下に「8 / 20」の形で文字数と上限を出す（`docs/site-settings-requirements.md` §5 と同じ）。
- 保存は Server Action。セッションの利用者の行だけを書き、値を検証してから書く。結果は「保存しました」、または欄ごとの理由（「20 文字以内で入力してください」「改行は使えません」）。空は許す。

### 6.2 署名

- 記事のページでは、日付・更新日・カテゴリが並ぶ行の先頭に表示名を置く。この行は項目を間隔だけで区切っているので、表示名もほかの項目と同じ間隔で並べ、「・」は使わない。版の履歴のプレビューも同じ部品（`components/PostArticle.tsx`）で描くので、同じ位置に出る。
- 走り書きのページでは、日付の後ろに「・」で区切って表示名を置く。日付が単独で置かれた行なので、区切りが要る。
- 色と大きさは、それぞれの行の日付と同じ。リンクにはしない（著者のページはまだ無い）。
- 表示名が空なら、区切りごと出さない。
- 一覧のカード、RSS、`og:` のメタデータには出さない（§8）。
- 署名はページを描くたびに `users` から読む。表示名を変えれば、次に開いたページから変わる。

## 7. 受け入れ基準

| ID  | 基準                                                                                                                       | 測り方                                                       |
| --- | -------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 1   | 書き換えの判定は、管理者なら常に可、著者なら自分の行だけ可、著者の無い行は管理者だけ可                                     | `lib/post-access.test.ts`                                    |
| 2   | 著者が他人の行に対して呼ぶと、`app/actions/posts.ts`・`app/actions/revisions.ts` のすべての export が拒み、DB が変わらない | `app/actions/posts.test.ts`、`app/actions/revisions.test.ts` |
| 3   | 著者が呼ぶと、`app/actions/tags.ts`・`app/actions/settings.ts` のすべての export が拒み、DB が変わらない                   | `app/actions/tags.test.ts`、`app/actions/settings.test.ts`   |
| 4   | 著者が他人の行を自動保存すると 403 で、DB が変わらない                                                                     | `app/api/drafts/route.test.ts`                               |
| 5   | 著者が他人の記事の編集画面・版の履歴・Markdown の書き出し・下書きのプレビューを開くと 404                                  | `e2e/multi-author.spec.ts`                                   |
| 6   | 著者の記事一覧と走り書きの一覧には自分の行だけが出る。管理者にはすべてが出る                                               | `e2e/multi-author.spec.ts`                                   |
| 7   | カードの検索は他人の下書きを返さない                                                                                       | `app/api/posts/search/route.test.ts`                         |
| 8   | 停止中の利用者はログインできず、既存のセッションはログインしていない扱いになる                                             | `app/actions/auth.test.ts`、`lib/dal.test.ts`                |
| 9   | 停止中の著者の公開中の行は、公開側の読み込み・件数・ライブラリから外れ、解除すると戻る                                     | `lib/posts.test.ts`、`lib/library.test.ts`                   |
| 10  | 表示名は 20 文字まで、改行なし、空を許す。自分の行だけを書く                                                               | `app/actions/account.test.ts`                                |
| 11  | 表示名があると記事と走り書きのページの日付の行に出て、空なら出ない                                                         | `e2e/multi-author.spec.ts`                                   |

基準 2・3 の「すべての export」は、テストがモジュールの export を列挙して呼ぶ形にする。名前を手書きで並べない。検査を忘れた新しい Action が、テストを足さなくても落ちるようにするためである（`docs/project-status.md` §7.3、2026-09-24 の合意）。

## 8. 先送り（OAuth の段）

- Google でのログインと、参加方針（`open` / `allowlist`）と許可リスト（`docs/project-status.md` §7.1・§7.3）。
- `/admin/users`: 利用者の一覧、役割の変更、停止と解除、停止中の著者の行をまとめて消す操作。
- 管理画面の一覧に著者の列を出すこと。管理者には他人の行も出るが、著者が 1 人もいない今は、列があっても情報が増えない。
- 署名を一覧のカード、RSS、`og:` に出すこと。著者のページ。
- `docs/embed-requirements.md` §24.9 の「自分の記事 / 全記事」のタブ。
- アップロードの所有と、参照の表による掃除（`docs/project-status.md` §7.3）。

# サイトのヘッダー 要件定義

- 状態: 設計済み、未実装（2026-10-15）
- 作成: 2026-10-15、Zenn・note・GitHub・ashunar0.dev のヘッダーを見比べ、ログインの有無でヘッダーを変える相談から
- 関連: `docs/project-status.md` §6・§7.3、`components/SiteHeader.tsx`、`app/admin/(list)/AdminSideNav.tsx`、`app/admin/(list)/ScreenHeading.tsx`
- 見た目の案: https://claude.ai/artifact/XoDTb7FhhkpwfY4LdnZLNf の「案 B」

公開ページと管理画面の一覧の画面がかぶるヘッダー（`SiteHeader`）の設計記録。ログインしていない人には読むための入口だけを、ログイン中の人には書くための入口とアカウントのメニューを出す。

---

## 1. 目的と前提

ヘッダーは「Tech Blog」とタグ・カテゴリ・走り書き・管理の 4 つのリンクを、ページと同じ地の上に線 1 本で区切って並べていた。そこには 3 つの問題があった。ページとの境目が弱いこと、今いるページが分からないこと、読者にも管理画面の入口が見えていること。もう 1 つ、幅 360px で 1 行がいっぱいで、ログイン中の入口を足す場所が無かった。

ログインできるのは今は管理者だけである（複数の著者の Google のログインは `docs/project-status.md` §7 で未実装）。ログイン中の表示は、著者がログインできるようになってもそのまま使える形にする（§8）。

## 2. 決定

- 公開側のリンクは「記事 ▾」と「走り書き」の 2 つにする。タグとカテゴリは、どちらも記事を探す入口なので「記事」のメニューにまとめる。走り書きは記事と並ぶ別の種類の中身なので、開かなくても見える場所に残す。案 A（並べて、狭い画面だけハンバーガーにまとめる）と案 C（すべてを「読む ▾」1 つに）は採らなかった。A は 360px でログイン中にメニューが 2 つ並び、C は公開側の入口がすべてクリックの奥に隠れる（オーナー、2026-10-15）。
- ログイン中だけ、右端に「投稿する」とアカウントのボタンを出す。`docs/project-status.md` §7.3 で先送りにしていたアカウントメニューを、ここで作る。
- **ログインしていない人には、ログインの入口を何も出さない。**「管理」はヘッダーから消し、「ログイン」と「投稿する」も出さない。読者は登録できないので、押してもログイン画面で行き止まりになる。管理者は `/login`（ログイン中なら `/admin`）をアドレスで開く（オーナー、2026-10-15）。
- ヘッダーの地は白（`--surface`）にして、ページの地（`--background`）と分ける。

## 3. 形

### 3.1 共通

- 地は `bg-surface`、下に 1px の線（`border-zinc-200`、ダークは `border-zinc-800`）。中の幅と左右の余白は今と同じ（外側の `px-4` と、内側の `max-w-page`。理由は `SiteHeader` のコメント）。
- 高さは今と同じ 61px（下の線を含む）の 1 つにし、幅でもログインの有無でも変えない。編集画面のヘッダー（`app/globals.css` の `.editor-header-bar`）がこの高さに合わせてあり、記事一覧と編集画面を行き来しても段が跳ねないようにしている（`e2e/editor-sticky-header.spec.ts` が比べる）。
- 左から順に、ブランド（`/` へのリンク。サイトのマークと名前。名前は管理者の設定で、既定は「Small Diffs」。`docs/site-settings-requirements.md` と `components/SiteMark.tsx`）、公開側のリンク「記事 ▾」「走り書き」。右端はログイン中だけ §3.3 のボタンを置く。
- 公開側のリンクは 14px の `font-semibold`。今いる区画のものは濃い色（`text-zinc-900`、ダークは `text-zinc-50`）、ほかは灰色（`text-zinc-500`、ダークは `text-zinc-400`）。灰色のものは hover（`@media (hover: hover)`）で濃くする。下線は付けない。
- 今いる区画は、パスから 1 つの関数で決める。
  - 記事: `/`、`/posts/…`、`/tags` と `/tags/…`、`/categories` と `/categories/…`、`/search` と `/search/…`（`docs/search-requirements.md` §5.2）
  - 走り書き: `/scribbles` と `/scribbles/…`
  - それ以外（管理画面、`/login`）はどちらでもない。
- 「記事」のメニューの項目は、上から「最新の記事」（`/`）、「カテゴリ」（`/categories`）、「タグ」（`/tags`）、区切り線の下に「検索」（`/search`、`docs/search-requirements.md` §5.1）。今開いているページがその一覧のときだけ、項目に `aria-current="page"` を付けて太字にする。「走り書き」のリンクにも、`/scribbles` にいるときだけ `aria-current="page"` を付ける。

### 3.2 ログインしていないとき

ブランドと「記事 ▾」「走り書き」だけを出す。右側は空ける。

### 3.3 ログイン中

ログインしているかどうかは `getOptionalSession()`（`lib/dal.ts`）で決める。管理者と著者で同じものを出す。

- 「投稿する」: 黒いボタン（`button-primary`）に「＋」のアイコンと「投稿する」の文字。押すとメニューが開き、「記事」（`/admin/posts/new`）と「走り書き」（`/admin/posts/new?kind=scribble`）を出す。見出しは付けない（ボタンの「投稿する」が既にそれを言っている。オーナー、2026-10-15）。
- アカウントのボタン: 直径 36px の丸に、`username` の最初の 1 文字を大文字で出す。色はタグの札と同じ `--chip-bg` と `--chip-fg`。`aria-label` は「アカウントのメニュー」。押すとメニューが開く。
  - 上に小さな灰色の文字で「<username> でログイン中」
  - 「ライブラリ」（`/admin/library`）
  - 「管理画面」（`/admin`）
  - 区切り線の下に「ログアウト」（`app/actions/auth.ts` の `logout` を呼ぶフォームのボタン）

### 3.4 幅 360px

- 1 行のまま、ブランド・「記事 ▾」・「走り書き」・右端のボタンを並べる。
- `sm` より狭い幅では、「投稿する」を「＋」だけの 40px 四方のボタンにする（`aria-label` は「投稿する」）。開くメニューは同じ。
- `sm` より狭い幅でログイン中のときは、ブランドの名前を隠してマークだけにする。名前はリンクの読み上げの名前として残す。名前とマークを並べると、「投稿する」とアカウントのボタンが 1 行に収まらない（2026-10-15 に測った。アカウントのボタンの右端が 357px で、列の右端の 344px を越えた）。ログインしていないときは右側が空いているので、名前も出す。
- 「投稿する」とアカウントのメニューは右端にそろえて開き、画面の外にはみ出さない。
- 設定した名前が長いときは、名前の文字が切れて「…」になり、「記事 ▾」と「走り書き」より先に縮む。名前はリンクの読み上げの名前（`aria-label`）なので、切れても全部が読まれる。

## 4. メニューの開き方と閉じ方

「記事」「投稿する」「アカウント」の 3 つのメニューは同じ作りにする。

- クリック（タップ）で開き、もう一度押すと閉じる。hover では開かない。
- 形は、ボタン（`aria-expanded`・`aria-controls`）とリンクの一覧のパネルにする。`ScreenHeading` の開閉と同じで、ARIA の `menu` の役割と矢印キーの操作は作らない（Tab で項目を順に移る）。
- 外側のクリックと Esc で閉じる（`components/editor/useDismiss.ts` の `useDismiss`）。Esc で閉じたときは、開いたボタンにフォーカスを戻す。
- 項目を選ぶと閉じる。一度に開くのは 1 つで、別のメニューを開くと前のものは閉じる。
- パネルの見た目は `ScreenHeading` のパネルに合わせる（`rounded-panel`、枠、`bg-surface`、影、項目は `text-sm` で hover で背景を薄く塗る）。

依存は足さない。

## 5. 管理画面への影響

記事一覧・走り書き・ライブラリ・タグの管理の画面も、このヘッダーをかぶっている（`app/admin/(list)/layout.tsx`）。

- ログアウトはアカウントのメニューだけに置く。左メニュー（`AdminSideNav`）と、狭い画面で見出しから開くメニュー（`ScreenHeading`）からは消す。
- 記事一覧と走り書きの一覧の見出しの行にある「新規作成」は消す。書き始めるのはヘッダーの「投稿する」から。一覧が空のときの「新規作成」（`EmptyPostList.tsx`）は、空の表示の呼びかけとして残す。
- 編集画面（`app/admin/posts`）はヘッダーを持たないまま変えない。

## 6. 先送り

- ログインしていない人への「ログイン」や「書いてみる」の入口。出すかどうかは、複数の著者の参加方針（`open` / `allowlist`、`docs/project-status.md` §7.1）と一緒に決める。`allowlist` では、押した人の大半が Google のログインの後で断られる。右側は空けてあるので、後で足してもほかの配置は変わらない。
- アカウントのボタンに出す名前と画像。表示名は §7.1 で未設計なので、今は `username` の頭文字にしている。
- テーマ（明るい・暗い）の切り替え、サイトのロゴ。ヘッダーの検索の入力欄は `docs/search-requirements.md` §7。

## 8. 複数の著者との関係

著者がログインできるようになれば、著者にも同じヘッダーが出る。管理者だけの項目（タグの管理、利用者の管理）は、管理画面の左メニューに置いたままにし、アカウントのメニューには入れない。表示名が決まったら（`docs/project-status.md` §7.1）、アカウントのボタンの文字と「<username> でログイン中」をそれに置き換える。

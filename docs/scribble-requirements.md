# 走り書き 要件定義

- 状態: 設計済み、未実装（2026-10-15）
- 作成: 2026-10-15、管理画面の左メニューに note・Zenn のようなページを足す相談から
- 関連: `docs/project-status.md` §2（スキーマの変更の手順）、`docs/link-card-requirements.md` §6.1（下書きと存在しない slug を同じに答える）、`docs/editor-requirements.md` §12.38（文字数）、`lib/posts.ts`、`scripts/upload-refs.mts`

1000 字に満たない短いメモを、記事とは別の場所に公開するための機能の設計記録。画面での名前は「走り書き」、コードと URL での名前は `scribble`。

---

## 1. 目的と前提

**目的**: 公開記事は 1000 字以上あるのが望ましい、というのが作者の基準である。それに満たない思いつきや調べた途中経過を、記事の一覧の質を下げずに公開できる場所を作る。

**前提**: 書き手は 1 人で、読者はログインしない（`docs/project-status.md` §7.1）。Zenn のスクラップのような、コメントを積み上げるスレッドは要らない。作者が欲しいのは短い記事である。

## 2. 決定

- **走り書きは `posts` の行である。** 種類を表す列 `kind` を足し、別のテーブルは作らない。エディタ、自動保存、作業コピー、リビジョン、タグ、アップロードの掃除が、何も足さずに走り書きにも効く。別のテーブルにすると、これらをすべて二重に持つことになる。
- **本文は 1 つ。** 記事と同じエディタで書く。
- **公開側に出るのは `/scribbles` だけ。** ホーム、カテゴリとタグのページ、RSS には出さない（§5）。
- **検索エンジンには載せない。** サイト全体の設定（`SITE_INDEXABLE`）にかかわらず、走り書きのページは noindex である。短いページが多いと、サイト全体が中身の薄いページとして評価されうるためである。
- **タイトルは必須。** 一覧、ページのタイトル、共有されたときのカードに要る。
- **カテゴリとサムネイルは持たない。** タグは持つ。

## 3. データ

### 3.1 `kind` 列

`posts` の末尾に `kind` を足す。値は `post` と `scribble`、既定値は `post` で、既存の行はすべて記事のままになる。この表は列を末尾に足す形の変更しか安全に通らない（`lib/db/schema.ts` の `posts` のコメント）。変更は `npm run db:generate` から `npm run db:migrate` で行う（`docs/project-status.md` §2）。

`kind` は作成のときに決まり、v1 では変わらない。種類を変える（走り書きを記事に育てる）設計は §7.1 にある。

### 3.2 持たない値

- `category`: 列は NOT NULL なので値は入るが、走り書きでは読まない。
- `thumbnail`: 常に空。本文の画像はサムネイルの代わりにならない。走り書きの `og:image` は、記事に画像が無いときと同じ `/og.png` である。

### 3.3 公開の状態

記事と同じ 3 つを持つ。

| 状態     | 列                | 走り書きでの扱い                                   |
| -------- | ----------------- | -------------------------------------------------- |
| 非公開   | `draft = true`    | 公開側では 404。ログイン中の作者はプレビューできる |
| 公開     | `draft = false`   | `/scribbles` の一覧と各ページに出る                |
| 限定公開 | `unlisted = true` | 一覧には出ず、URL を知っている人だけが読める       |

新しい走り書きは非公開で始まる。公開した後の編集は記事と同じく作業コピー（`draft_content`）に入り、「更新」するまで公開中のページは変わらない。

## 4. 種類で絞る場所

**機構**: 行を読む関数が種類を絞る。呼び出し側の各ページには任せない。絞り忘れた 1 か所から、走り書きがホームや RSS に漏れるためである。

| 関数（`lib/posts.ts`）                | 返す種類     | 理由                                                                                                       |
| ------------------------------------- | ------------ | ---------------------------------------------------------------------------------------------------------- |
| `getAllPosts`                         | 記事だけ     | ホーム、RSS                                                                                                |
| `getPostsByTag`・`getPostsByCategory` | 記事だけ     | タグとカテゴリのページは記事のもの                                                                         |
| `getAllTags`・`getAllCategories`      | 記事だけ     | 公開側の件数が、そのページに並ぶ件数と合うように                                                           |
| `getPostBySlug`・`getDraftBySlug`     | 記事だけ     | `/posts/<slug>`、内部リンクカード、`/api/link-title`。走り書きの slug には、存在しない slug と同じに答える |
| `listAllPosts`                        | 記事だけ     | 管理画面の記事一覧                                                                                         |
| 走り書き用の対になる関数              | 走り書きだけ | `/scribbles`、`/scribbles/<slug>`、管理画面の走り書きの一覧                                                |
| `getPostForEdit`                      | 両方         | エディタは id で開き、種類を問わない                                                                       |

種類を問わないままにするもの:

- アップロードの掃除。`referencedInDb`（`scripts/upload-refs.mts`）は `posts` のすべての行とリビジョンを読むので、走り書きに貼った画像も消されない。
- タグの辞書の操作と `tagUsage`（`lib/tags.ts`）。管理画面のタグの件数は、走り書きが使うタグも数える。消してよいかの判断に要るためである。
- リンクカードのピッカーの検索（`/api/posts/search`）は記事だけを返す。v1 では走り書きをカードにしない（§7.2）。

## 5. 公開側

見た目は 2026-10-15 に 3 案から選んだタイムラインの形である。

- `/scribbles`: 公開中の走り書きを、公開日の新しい順に縦に積む。左に日付と縦の線、右に白いカードを置き、カードはタイトル、本文、タグの順に持つ。
- **一覧のカードは本文を全文で描き、決まった高さで切る。** 描画は各ページと同じ経路（markdown からサニタイズを経た HTML）を通る。高さを超えたカードは下端を白く消し、「続きを読む」で各ページへ送る。1000 字に満たない本文の多くは切れずに出る。本文の書き出しだけの抜粋（`excerptFromBody`）にしないのは、コードブロックと画像が消え、一覧で読めるという狙いが失われるためである。
- 一覧のカードは埋め込みの iframe を描かず、リンクとして出す。動画の埋め込みが並ぶと一覧が重くなるためである。
- 切る高さ（仮に 300px）、埋め込みの代わりの見た目、一覧のページ分けの件数は、実装のときに実物で決める。
- `/scribbles/<slug>`: 上に一覧へ戻るリンク、その下の白いカードに日付、タイトル、本文、タグを置く。カテゴリと目次は出さない。目次は 1000 字に満たない本文には要らない。
- `/posts/<slug>` は走り書きの slug に 404 を返し、`/scribbles/<slug>` は記事の slug に 404 を返す。
- 走り書きのページと一覧は `robots: { index: false }` を出す。`app/robots.ts` で `/scribbles` を disallow にはしない。disallow にするとクローラは meta を読まないまま、リンクから見つけた URL を検索結果に出しうる（`app/robots.ts` の `robots` のコメントと同じ理由）。
- サイトのヘッダーの「タグ」「カテゴリ」と「管理」の間に「走り書き」へのリンクを置く。

## 6. 管理画面

- 左メニュー（`AdminSideNav`）の「記事一覧」と「タグの管理」の間に「走り書き」を足す。
- 走り書きの一覧は、記事一覧と同じ表で、公開・非公開・限定公開・未公開の変更ありの印を各行に出す。状態のタブ、並び替え、タイトルの検索は記事一覧と同じにし、カテゴリの絞り込みは出さない。
- 一覧の見出しの行に「新規作成」を置く。作られる行は `kind = scribble` である。
- エディタは記事と同じものを使う。記事の設定から、カテゴリとサムネイルの欄を出さない。文字数は既存の表示（`docs/editor-requirements.md` §12.38）で足り、上限は設けない。

## 7. 先送り

### 7.1 走り書きを記事に育てる

育った走り書きを、slug を保ったまま記事に変える。v1 では作らない。作るときの形は次のとおり決めてある。

- `kind` を作業コピー（`DraftContent`）の一部にする。非公開の走り書きはその場で記事になる。公開中の走り書きは、作業コピーで種類が変わり、「更新」したときに初めて `/posts` に移る。こうしないと、「記事にする」を押した瞬間に未完成の文章がホームと RSS に出る。
- 種類が変わった後の古い URL は、もう一方の URL へリダイレクトする（`/scribbles/<slug>` → `/posts/<slug>`）。共有されたリンクが切れないようにするためである。
- 記事を走り書きに戻すことはしない。RSS の購読者に配った項目が消える。

### 7.2 走り書きを指すリンクカード

内部リンクカードの参照は `/posts/<slug>` の形に限られている（`lib/link-card-href.ts` の `INTERNAL_CARD_HREF`）。走り書きへのリンクは、v1 では普通のリンクとして描かれる。カードにするには、参照の形、`resolveCard`、ピッカーの検索を広げる。

### 7.3 ライブラリ

管理画面の「ライブラリ」（お気に入りの記事）は、走り書きを作った後で改めて考える（作者、2026-10-15）。書き手が 1 人で読者がログインしない今は、取っておく対象がほとんど自分の記事しかない。

## 8. 受け入れ基準

| ID  | 基準                                                                                 | 測り方 |
| --- | ------------------------------------------------------------------------------------ | ------ |
| 1   | 既存の行は移行の後もすべて `kind = post` である                                      | 未定   |
| 2   | §4 の表で「記事だけ」の関数は、公開中の走り書きがあっても走り書きを返さない          | 未定   |
| 3   | 走り書きは `/scribbles` に出て、ホーム、カテゴリとタグのページ、RSS に出ない         | 未定   |
| 4   | `/posts/<走り書きの slug>` と `/scribbles/<記事の slug>` はどちらも 404              | 未定   |
| 5   | 走り書きのページと一覧は noindex を出す。`SITE_INDEXABLE` が真でも同じ               | 未定   |
| 6   | 非公開の走り書きは、ログインしていなければ 404、ログイン中ならプレビューできる       | 未定   |
| 7   | 走り書きにだけ参照されている画像は、アップロードの掃除で消されない                   | 未定   |
| 8   | 管理画面の記事一覧に走り書きは出ず、走り書きの一覧に記事は出ない                     | 未定   |
| 9   | 走り書きのエディタの設定にカテゴリとサムネイルの欄が出ない                           | 未定   |
| 10  | 内部リンクカードが走り書きの slug を指すと、存在しない slug と同じ普通のリンクになる | 未定   |
| 11  | 一覧のカードは高さを超えると切れて「続きを読む」が出て、超えなければ全文が出る       | 未定   |
| 12  | 一覧のカードに埋め込みの iframe は出ず、リンクになる                                 | 未定   |

測り方の列は、テストを書いたときにそのファイル名で埋める。

## 9. 複数の著者との関係

v1 は書き手 1 人で作る。複数の著者（`docs/project-status.md` §7）が入ったときに作り直さずに済むよう、ここに関係を書いておく。

**そのまま効くもの**: 走り書きは `posts` の行なので、§7.3 が記事に足すもの — `posts.authorId` による所有、Server Action での所有者か管理者かの確認、管理画面の一覧を自分の行に絞ること、著者ごとのアップロードの参照テーブル — が走り書きにも効く。走り書きのための追加の作業は無い。

**v1 で備えておくこと**:

- 一覧のカードの日付の行に、著者名を置く場所を空けておく。v1 では何も出さない。
- §4 の走り書き用の関数は、絞り込みの条件を引数のオブジェクトで受け取る。著者の条件は後から足す。

**複数の著者を入れる前に決めること**:

- 公開側に出す著者の名前。`users` にはログイン用の `username` しか無く、§7.3 が足すのも `email` と `googleSub` で、公開してよい名前が無い。記事の署名にも同じものが要るので、`docs/project-status.md` §7.1 に書いた。
- 参加方針が `open` のときの走り書きの公開。どの Google アカウントでも著者になれるなら、ログインした直後に短文を公開できる。走り書きは記事より手軽なぶん、宣伝や荒らしが最初に来る場所になる。noindex は検索目当ての宣伝には効くが、管理者が他人の走り書きを非公開にする操作と、まだ設計していない BAN が、`open` での公開の前提になる。
- 一覧を全員の 1 本にするか、著者ごとにするか。v1 の `/scribbles` は全員の 1 本である。著者が増えたら、著者での絞り込みか著者ごとのページを足す。

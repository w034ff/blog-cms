# トップページと記事一覧 要件定義

- 状態: 実装済み（2026-10-18）
- 作成: 2026-10-18、Zenn・Qiita・ガジェッター（gadgeteer.jp）・note のトップを Chrome DevTools MCP で測り、オーナーと描き比べた相談から
- 関連: `app/(site)/page.tsx`、`app/(site)/categories/[category]/page.tsx`、`app/(site)/tags/[tag]/page.tsx`、`components/PostCard.tsx`、`components/PinnedPost.tsx`、`components/PostListNav.tsx`、`lib/post-list.ts`、`lib/pinned-post.ts`

トップページ（`/`）・カテゴリのページ・タグのページの記事一覧を、行からカードに変え、カテゴリのタブ、管理者が選ぶピックアップ、ページ送りを足した変更の設計記録。

---

## 1. 目的と前提

**目的**: 一覧の 1 画面に入る記事を増やし、技術記事とブログの 2 種類があることを開いた時点で伝える。管理者が読ませたい 1 本を、新しさと関係なく先頭に出せるようにする。

**前提**: 公開中の記事はどれも写真を持たず、一覧の絵はカテゴリ色のマーク（`docs/category-mark-requirements.md`）である。書き手は 1 人で、いいねの数は常に 0（同 §7）。走り書きはトップにもカテゴリとタグのページにも出ない（`docs/scribble-requirements.md` §2）。

## 2. 決定

- **一覧はカードを 2 列に並べる。** カードは左に 72px 角の絵、右にタイトル（3 行まで）と日付・カテゴリを置く。説明文とタグは出さない。`md` 未満は 1 列。トップ・カテゴリのページ・タグのページは同じカード（`PostCard`）を使う。
- **理由**: 画面 1000px の高さに入る記事の数を、案ごとに実際の画面で測った（2026-10-18）。

  | 形                                         | 1280px  | 360px  |
  | ------------------------------------------ | ------- | ------ |
  | 以前の行（説明文 2 行とタグ、160×96 の絵） | 4.8 件  | 3.6 件 |
  | 絵が上のカード 3 列（16:9）                | 7.8 件  | 3.7 件 |
  | 絵が左のカード 2 列（採用）                | 14.2 件 | 8.1 件 |

  絵が上のカードは 360px で 1 列になり、絵の分だけ縦に伸びるので、スマホでは行の一覧と変わらなかった。引き換えに説明文とタグが一覧から消える。説明文はピックアップの枠（§3）と記事のページに、タグは記事のページとヘッダーの「記事 ▾」の「タグ」に残る。

- **トップとカテゴリのページの上にタブを置く。** 「すべて」「技術記事」「ブログ」の 3 つで、押すと `/`・`/categories/tech`・`/categories/blog` へ移る。トップの中で絞り込む形（`/?category=tech`）にしないのは、同じ一覧に URL が 2 つできるためである。今いるページのタブに `aria-current="page"` を付ける。
- タブはピックアップの枠より上に置く。枠は「すべて」にだけ出るので、下に置くとタブを押すたびにタブの位置が上下に動く。Zenn も同じ並びである。
- **トップとカテゴリのページは見える見出しを持たない。** タブが一覧の名前を言っており、押した先で同じ名前を見出しにすると、ボタンの言葉を見出しで繰り返すことになる（`docs/site-header-requirements.md` §3.3）。`h1` は `sr-only` で残す（トップは「最新の記事」、カテゴリのページはカテゴリ名）。カテゴリのページの件数「(5)」はこれに伴って出さなくなった。
- タグのページはタブを持たない。タグはカテゴリを横切る分け方で、どのタブも今いるページにならないためである。見出し「#名前 (件数)」はそのまま見せる。件数はすべてのページの合計である。
- カテゴリに公開中の記事が無いとき、そのページは 404 ではなく「まだ記事がありません。」を出す。タブはどの一覧にも常に 3 つ出るので、押せるタブの先が 404 になってはいけない。カテゴリの一覧に無い id（`/categories/tech-notes`）は今までどおり 404 である。
- ヘッダーの「記事 ▾」から「カテゴリ」を外した（`docs/site-header-requirements.md` §3.1）。`/categories` のページは残す。ブックマークや外からのリンクが 404 にならないためで、ヘッダーからはもうたどれない。

## 3. ピックアップ（トップに固定した記事）

- **管理者は記事を 1 本だけトップに固定できる。** 固定した記事は、トップの 1 ページ目のタブの下に「ピックアップ」の札を付けて大きく出す。16:9 の絵、タイトル、日付・カテゴリ、説明文 3 行を持つ。
- **保存先は `app_settings` の `pinned_post_id` である**（`lib/pinned-post.ts` の `PINNED_POST_KEY`）。`posts` に列を足さないのは、固定がサイトに 1 つの値で、サイトの名前と同じく管理者のものだからである。表の作り直しも移行も要らない。変えられるのは管理者だけで（`docs/site-settings-requirements.md` §2）、Server Action（`app/actions/settings.ts` の `pinPostAction`）が拒む。
- 操作は管理画面の記事一覧の各行の「⋯」にある「トップに固定」と「固定を外す」である。管理者にだけ、公開中の記事の行にだけ出す。固定中の行には「ピックアップ」の札を付ける。サイトの設定の画面にも、今の固定と「固定を外す」を出す（`docs/site-settings-requirements.md` §10）。
- 固定できるのは、トップの一覧に出る記事だけである（公開中、限定公開でない、記事であって走り書きでない、著者が停止中でない）。Action はトップと同じ `getAllPosts` で確かめる。
- 固定した記事が後で非公開になったり、著者が停止されたりしたら、枠は出ない。最新の記事で代わりに埋めない。保存した id は残るので、記事を公開に戻せば枠も戻る。
- 固定した記事は下のカードの一覧には出さない。一覧はこの記事を除いてから 20 件ずつに分ける（§4）。
- 360px（`sm` 未満）では枠の絵を出さない。絵だけで最初の画面の大半（約 440px）を埋めたためである。札・タイトル・日付・説明文は出す。
- カテゴリのページとタグのページには枠を出さない。

## 4. ページ送り

- 一覧は 1 ページ 20 件（`lib/post-list.ts` の `POSTS_PER_PAGE`）。走り書きの一覧（`SCRIBBLES_PER_PAGE`）と同じ数で、偶数なので 2 列が埋まって終わる。
- 2 ページ目からは `?page=2` の形の URL になる。1 ページ目は `?page` の無い URL だけである。数でない値や 1 未満は 1 ページ目として読む（`lib/scribble-list.ts` の `parsePageNumber`）。最後のページより後は 404。
- 一覧の下に「← 新しい記事」と「古い記事 →」を置く。走り書きの「← 新しい走り書き」「古い走り書き →」と同じ形である。1 ページに収まるときは何も出さない。
- 2 ページ目からのタブのタイトルは「最新の記事 (2 ページ目)」の形にする（`pagedTitle`）。

## 5. 却下した案

どの案も、実際のアプリに仮のページとして描き、1280px と 360px、明るい配色と暗い配色で比べた。

- **行の一覧を白い枠に入れ、右の列に「よく使われるタグ」（Qiita 型）** — 既にある部品だけで作れて説明文も残るが、1 画面の件数は変わらない。360px では枠の分だけタイトルの列が狭くなる。
- **絵が上のカード 3 列（note・ガジェッター型）** — 写真の無い記事ばかりの今は、同じ色の大きなタイルが並び、`docs/category-mark-requirements.md` §6 の案 F と同じ失敗（読み込みに失敗した画像に見える）になる。スマホの件数も増えない（§2 の表）。記事に写真が増えたら見直す価値がある。
- **別のページに分ける・管理画面で形を切り替える** — 同じ一覧が 2 か所にできるか、読者が見るのは常に一方なのに 2 つの形を保守することになる。
- **「もっと見る」で下に足す・無限スクロール** — JavaScript が要り、記事から戻ると足した分が消え、何ページ目かを指す URL が無い。無限スクロールはフッターに届かない。
- **ページ番号を並べる（1 2 3 …）** — 記事が数百になってからでよい。

## 6. 先送り

- **人気順の並べ替え**: 並べる数が無い。いいねは書き手が 1 人の今は常に 0 で、ライブラリの閲覧の記録はログインした人の履歴であって記事ごとの閲覧数ではない。著者が増えていいねが集まり始めたとき、または閲覧数を数えると決めたときに見直す。足すなら `?sort=` の形にすれば、タブ（ページを移る）ともページ送り（`?page=`）とも両立する。
- **カードに著者名といいねの数を出す**: `docs/multi-author-requirements.md` §9.10 と `docs/category-mark-requirements.md` §7 のまま。
- **固定を複数にする・期限を付ける**: 1 本で足りている。

## 8. 他の文書との関係

- `docs/category-mark-requirements.md` §3.2・§5 — 一覧の絵の枠と、狭い画面の一覧の扱い。この変更で枠が 72px 角になり、説明文とタグはどの幅でも出なくなった。
- `docs/site-header-requirements.md` §3.1 — 「記事 ▾」の項目。
- `docs/summary-requirements.md` §4 と `docs/search-requirements.md` §7 — 一覧のカードに説明文が出ることを前提にしていた記述と、一覧をカードにするときに決めるとしていた検索結果の札の地。
